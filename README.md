# Album Factory

Сервис подготовки выпускных альбомов для фотографов. Первый рынок — Россия. Целевая модель — общий макет с вариантами учеников и учительским вариантом; платные и подарочные экземпляры учитываются отдельно.

## Состояние

Локальный пилот содержит ядро PDF/CSV, FastAPI-сервер, интерфейс V2, загрузку и съёмки, сортировку V3, ручные исправления и клиентский выбор. Редактор мастер-макета подключён к серверному хранению, публикации комплектаций и генерации заказов. Инструкция и точные границы: [редактор мастер-макета](docs/master-editor.md), [редактор готового макета](docs/proof-editor.md). Допечатная подготовка требует дальнейшей реализации. Данные локального пилота не отправляются в облако.

Актуальная модель: [правила заказа](docs/domain-model.md), [каталог и автовёрстка V2](docs/domain-model-v2.md), [план продукта](docs/product-plan.md), [сессии реализации](docs/development-roadmap.md), [концепция редактора и ИИ-помощника](docs/layout-editor-ai.md). Основные правила заказа датированы 24.09.2026; концепция редактора добавлена 25.09.2026. Экспортированные ранее документы в output — исторические снимки; текущий источник требований находится в docs.

## Заказы и этапы

Слева — этапы работы, каждый открывает очередь заказов с одной кнопкой следующего шага; счётчик показывает, сколько заказов ждут фотографа. Главная — обзор: список задач, отчёт (заказы, альбомы, выручка) и доска процесса. Этапы: Загрузить фото → Проверить фото → Собрать анкеты → Сверстать макет → Согласовать макет → Напечатать → Доставить → Архив. Этап хранится на сервере и меняется действиями фотографа на странице заказа: первая загрузка фото переводит заказ из «Загрузить фото» в «Проверить фото», «Отправить на анкеты» выдаёт ссылку и коды класса, «Создать макет», «Отправить на согласование», «Отправить в печать». Печать, доставку и архив фотограф отмечает вручную. Съёмки внутри заказа — папки с датой; их можно переименовать или удалить целиком вместе с фотографиями, если фотографии не использует текущая опубликованная редакция альбома. Перестройка коллажей в готовом макете описана отдельно: [collage-editing.md](docs/collage-editing.md).

## Ограничения клиентского доступа и производства

Код входа позволяет читать сводку; менять распределение тиража и получение может заказчик с кодом управления до отправки в печать. После восьми неверных попыток соответствующий код блокируется на 15 минут, включая правильный ввод; после окончания блокировки счётчик начинается заново. Успешный вход или переиздание кодов сбрасывает счётчик.

Удаление или перенос выбранного портрета освобождает выбор и отправку анкеты: участник выбирает оставшийся портрет заново. Фотографии опубликованного макета защищены от удаления; сначала нужно опубликовать редакцию без них. Пропавшие файлы блокируют публикацию и экспорт макета.

Число подарочных экземпляров задаёт фотограф; заказчик может только перераспределить их между получателями. Разрешение производства фиксирует снимок тиража, распределения и получения. На этапах печати, доставки и архива сводка недоступна для изменений; экспорт сверяется с хешем снимка. Подробности исправлений и ограничения прежних заказов: [Б1–Б7 в мастер-аудите](docs/service-master-audit-2026-09-30.md). Производственный комплект теперь содержит реальные PDF и JPEG опубликованной редакции, с копиями фотографий и шрифтов. После разрешения производства макет доступен только для просмотра. Если отдельного альбома учителя нет, фотограф выбирает опубликованный вариант для подарка перед печатью. Правила, скачивания и ограничения RGB: [производственный комплект](docs/production-export.md).

## Мастер-макеты

В главном меню откройте «Мастер-макеты» → создайте дизайн и первую комплектацию с ценой → отредактируйте её на холсте Fabric.js → при необходимости создайте комплектации на её основе → опубликуйте версию → выберите комплектацию в новом заказе → создайте макет по материалам заказа. Виньетки расширяются по составу класса, общие разделы сохраняют свой объём, личные развороты повторяются по ученикам. Общего бюджета разворотов нет.

Для веб-сервиса: `pip install -e '.[web,test]'`, затем `python -m uvicorn album_factory.server:app --host 127.0.0.1 --port 8000`. Откройте `http://127.0.0.1:8000/`.

## Запуск CLI

Python 3.11+. В виртуальном окружении установите проект: `pip install -e '.[test]'`.

`python -m album_factory.cli examples/order.json --output output/first-proof --font /absolute/path/to/cyrillic-font.ttf`

Демонстрационные изображения создаёт `python scripts/make_demo.py`. Это геометрические тестовые карточки с номерами, не фотографии людей. Тестовые имена вымышлены. Реальные JPEG можно подставить в JSON, указав относительные пути внутри папки заказа и связи персон с фотографиями.

В этой рабочей среде используется Python из bundled runtime; конкретные установленные версии приведены в `requirements-tested.txt`. Для production потребуется воспроизводимая сборка с полным lock-файлом.

## Контракт

`schema_version: 1`; `order` содержит id, school, class_name, year, copies. `people` — упорядоченный список id, first_name, last_name, role (student/teacher), quote, portrait (photo id). `photos` — id, path, category (portrait/class/group), people (список person id). `shared_photos` задаёт порядок общих и групповых страниц.

Один человек связан с несколькими фотографиями; одна общая фотография может быть связана с несколькими людьми. Персона и покупка экземпляра — разные понятия. Текущий шаблон включает всех перечисленных персон и не требует покупки экземпляра учителем.

Проверяются уникальность id, наличие и формат файлов, границы локальной папки (включая символические ссылки), принадлежность портрета персоне, роль и категории. Слишком длинный текст не обрезается: генерация выдаёт ошибку. CSV защищает текстовые ячейки от интерпретации как формул.

Выход: `album-proof.pdf`, `selections.csv`, `manifest.json`. Одна обложка, шесть портретов на странице, отдельный раздел учителей при их наличии, по странице на общую фотографию. Центрированное кадрирование портретов пока не учитывает лицо. Порядок участников соответствует входному списку. Шрифт встраивается в PDF; неподдерживаемые символы отклоняются.

`approval_matches` проверяет только совпадение отпечатка содержимого; это не авторизация и не юридическое согласование. Отпечаток зависит от шаблона, данных участников, порядка, выбранных фото и байтов оригиналов. Изменение числа печатных экземпляров не меняет содержимое общего альбома. Неизменяемое хранение оригиналов в будущем сервере необходимо для защиты от изменения файлов во время генерации.

## Проверки

`python -m unittest discover -s tests -v`

Тесты покрывают пагинацию, переменное число учителей, ошибочное сопоставление портрета, изменение версии, выход за папку заказа, формулы CSV, переполнение текста и структуру PDF. Проверка физической печати и нагрузка 300 файлов остаются для следующих пакетов.

## Ограничения первого модуля

Контрольный RGB PDF размером 210 × 280 мм. Нет вылетов, ICC-профиля, PDF/X, расчёта обложки и корешка или гарантии приёма типографией. Разрешение ниже 300 DPI даёт предупреждение, не блокировку: это сознательно контрольный экспорт. PNG поддерживается для локальных тестов; веб-MVP планируется с JPEG.

Локальный инструмент рассчитан на доверенный манифест фотографа, не на непосредственный запуск через публичный API. Для production нужны изоляция обработчиков, лимиты памяти/пикселей и времени, антивредоносная обработка загрузок, транзакции результатов, разграничение доступа и неизменяемые версии объектов.

## Общие фотографии

Общая съёмка анализируется на этом компьютере: люди и их число, лица и связь с персонами из портретов, крупность плана, резкость и закрытые глаза, серии похожих кадров, события по времени, сцена и эстетическая оценка. В заказе у общей съёмки есть вкладки «Лучшие», «Серии», «Брак» и «Люди»; фотограф исключает снимки, отмечает обязательные и главные, связывает неопознанных людей с учениками. Мастер-макет задаёт слотам роли, а генератор подбирает снимки на весь альбом с учётом покрытия учеников. Подробно: [общие фотографии](docs/general-photos.md).

Модели (около 230 МБ, в git не хранятся) устанавливаются командой `python scripts/fetch_models.py`; `--check` проверяет контрольные суммы. Без необязательных моделей анализ продолжает работать с уменьшенным набором признаков.

## Личный кабинет клиента

Откройте заказ на этапе «Фото» → «Отправить на анкеты». Кабинет рассчитан прежде всего на телефон.
Главный экран — «Статус заказа»: карточки этапов «Выбор портретов», «Согласование макета»,
«Доставка». Активный этап
выделен цветом, будущие — серые, завершённые собраны внизу.

Вход по коду входа — это аккаунт для родителей: выбор портрета, подпись (имя, фамилия, цитата до 300 символов)
и просмотр макета. Один портрет на персону сохраняется в SQLite. Кнопка аккаунта в шапке открывает
«Смену аккаунта»: код управления переводит в аккаунт заказчика, который вносит правки и согласует макет.

После публикации макета карточка «Согласование макета» открывает развороты по вариантам (общий,
именные), каждый разворот можно открыть крупно и листать. Внизу — «Всё в порядке» (тираж, получение,
согласование) и «Нужны правки». Правки двух видов: «Ошибка в имени» (выбрать человека, ввести новые данные —
имя сразу сохраняется для следующей сборки) и «Другая ошибка» (выбрать разворот и описать проблему).
Пока есть неучтённые правки, согласовать макет нельзя; заказчик может их отозвать. Фотограф видит правки
в статусе заказа и в списке «Все заказы», отмечает выполненные, а публикация новой версии закрывает остальные.

Ссылка предоставляет доступ ко всем персонам одного заказа. Это локальный пилот:
персональных учётных записей и публичного размещения пока нет.

## Каталог школ и учителей

При создании заказа обязательны название школы и город. Существующая школа подставляет
город; для старой карточки без города его нужно дописать. Новая пара «название + город»
сохраняется в каталоге вместе с заказом. Одинаковые названия в разных городах — разные школы.
Город сохраняется в заказе и доступен в текстовых полях мастер-макета («Город», «Название школы»).

Главное меню → «Каталог школ» → школа: разделы «Учителя», «Фото на разбор», «Заказы».
Есть поиск по ФИО/предмету, фильтры без портрета, выбора класса и архива, создание заказа
с подставленной школой. Каталог принадлежит студии. Учителя и портреты переиспользуются
между классами; дата назначения портрета видна в карточке. Учитель уходит в архив с возможностью
восстановления; выбранные ранее заказы сохраняют его в составе. Дубли можно объединить явно,
кроме карточек, используемых заказами в печати или архиве. Школу с заказами удалить нельзя.

Фотографии загружаются на странице школы или в заказе на вкладке «Учителя»; прежняя папка
«Учителя» во вкладке «Фото» также работает. Кадры группируются по лицам; без моделей каждый
остаётся отдельной группой. «Исправить» позволяет переносить готовые кадры между группами.
Кадр можно рассмотреть крупно. Фотограф выбирает учителя и отдельно нажимает «Сохранить портрет».
Класс по коду входа может подписать учителя без портрета; заменить уже выбранное фото может
фотограф. Подписанные группы уходят из разбора, но исходники и прежний портрет сохраняются:
в «Последних подписях» фотограф может отменить актуальное назначение. Если портрет затем
изменён, отмена старого назначения запрещена. Сохранённые исходники занимают место до удаления
школы; автоматическая очистка пока не предусмотрена. Повторная загрузка того же файла не создаёт
дубль даже после подписи. Фото учителей не входят в лимит фотографий заказа.

Состав альбома, классный руководитель и предмет в конкретном классе задаются на вкладке заказа
«Учителя». Предмет не меняет другие классы и карточку каталога. В кабинете клиента просматривать
и заполнять черновик может любой по коду входа; сохранить состав и предметы — ответственный
с кодом управления. Черновик не теряется после ввода кода или подписи фотографии.

Смена школы требует подтверждения и сбрасывает прежний состав; фотографии остаются у прежней
школы. В печати, доставке и архиве школа, класс и состав зафиксированы. Макет содержит собственный
снимок данных и копии портретов. Изменение школы, города, учителей, предметов или портретов вызывает
напоминание обновить макет; сохранение того же состава не вызывает ложного предупреждения.
Подробности проверки и миграции: [школы и учителя](docs/schools.md).

## Проверка готового макета

После загрузки портретов откройте заказ → «Макет» → «Создать макет», затем «Открыть
редактор макета». Редактор повторяет внешний вид редактора мастер-макета, но оставляет
действия этапа проверки: пролистать альбом каждого человека, заменить фото из панели
по человеку и съёмкам (или перетащить на рамку, или загрузить новый снимок), поправить
кадр, исправить или скрыть подпись, добавить, удалить и переставить развороты, вернуть
исходное, отменить правку. Правки общих разворотов по умолчанию идут всем; режим «Только
этот альбом» меняет только одного человека, у разных людей может быть разное число
разворотов. Каждого
человека фотограф отмечает проверенным; правка, изменившая его альбом, снимает отметку.
Вкладка «Проверка» ведёт к ошибкам и предупреждениям, ошибки блокируют PDF и публикацию.
«Опубликовать» показывает сводку и публикует редакцию классу; опубликованную редакцию
можно открыть для сравнения. «Обновить из данных заказа» сохраняет совместимые правки,
а несовместимые показывает как конфликты. Подробно: [редактор готового макета](docs/proof-editor.md).

## Целевые изменения после локального пилота

Общий вход класса по ссылке и четырёхзначному PIN; отдельный PIN управления вместо персональных аккаунтов родителей. Заказчик хранится с ФИО/контактом. В MVP входят школы/учителя, дизайны/издания/предложения, варианты учеников и учительский вариант, распределение платных/подарочных копий, адрес/способ получения, сводка до PIN и одно согласование всего заказа. Производство разрешает фотограф. Полный контракт — docs/domain-model.md и docs/domain-model-v2.md; наличие этого описания не означает реализацию.

Текущий `approval_matches` проверяет только содержание локального PDF. Для целевой модели необходим отдельный снимок согласования, включающий распределение экземпляров, стоимость и получение; изменение тиража может не менять байты PDF, но меняет согласуемый заказ.

Уточнения целевого сценария: фото фиксируется при выборе («Отправить анкету» завершает заполнение); макеты генерирует и публикует фотограф, клиентского редактора нет. Одно издание на заказ; число разворотов нового мастер-макета вычисляется по правилам разделов; фотограф может добавить или убрать разворот у отдельного человека. Выбранный портрет учителя хранится отдельной копией в справочнике школы; файлы заказа удаляются по правилам заказа. Клиенту не показываются цены или денежные расчёты. Правка согласованного макета предлагает повторное согласование либо явную ответственность фотографа; изменение количества/получения само по себе повторного согласования не требует.
