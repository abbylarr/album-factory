# Общие фотографии: от загрузки до макета

Обновлено 28 сентября 2026. Статус: этапы M1–M5 спецификации реализованы; облачная LLM (M6) не подключена. Документ описывает путь общих фото заказа: загрузка → локальный анализ → проверка фотографом → роли слотов в мастер-макете → подбор на весь альбом → ручная замена в рабочем макете. Связанные документы: [shoots.md](shoots.md), [domain-model-v2.md](domain-model-v2.md), [master-editor.md](master-editor.md).

## 1. Принципы

- **Анализ только локальный.** Пиксели не покидают компьютер студии. LLM — возможный будущий этап, выключенный по умолчанию и только с согласия студии (раздел 10).
- **Персоны — только из портретов.** Общие съёмки не создают персон; лица общих фото связываются с существующими персонами автоматически или фотографом. Люди не из класса остаются неопределёнными.
- **Учителя на общих фото не распознаются** (решение владельца продукта). Роли и фильтры учителя в подборе нет.
- **Решения фотографа главнее автоматики.** Ручные связи лиц, исключения, отметки и выбор лучшего кадра переживают повторный анализ и обновление портретов.

## 2. Модели

| Задача | Модель | Файл в `models/` | Лицензия |
|---|---|---|---|
| Лица и 5 точек | YuNet (OpenCV Zoo) | `yunet.onnx` | MIT |
| Опознание | SFace (OpenCV Zoo) | `sface.onnx` | Apache 2.0 |
| Мимика: моргание, улыбка, наклон головы | MediaPipe Face Landmarker, читается OpenCV DNN | `face_landmarker.task` | Apache 2.0 |
| Люди и 17 точек тела | RTMO-s (OpenMMLab), onnxruntime | `rtmo-s.onnx` | Apache 2.0 |
| Сцена, эстетика, постановка/репортаж, почти-дубли | CLIP ViT-B/32, квантованный ONNX (Xenova) | `clip/*` | MIT |

`python scripts/fetch_models.py` скачивает недостающие файлы и сверяет SHA-256; `--check` только проверяет. Модели занимают около 230 МБ и не хранятся в git. Если необязательной модели нет, анализ продолжается без соответствующих полей (`GeneralVision.features`). Новая зависимость — `onnxruntime` (extra `web`).

Скорость на тестовом Mac: 0,4–1,6 с на кадр (в среднем ~0,85 с), 19 снимков примера — 16 с вместе с портретами.

## 3. Загрузка и очередь

Загрузка та же (`POST /api/orders/{id}/photos?shoot_id=`), общие фото получают статус `pending` и идут через ту же фоновую очередь, что и портреты: `pending → processing → ready | error`. Ошибку повторяет «Повторить обработку». Общие фото, загруженные до появления анализа, один раз ставятся в очередь при запуске сервера. Кнопка «Проанализировать заново» перезапускает всю съёмку.

Время съёмки берётся из EXIF `DateTimeOriginal` оригинала (смещение часового пояса отбрасывается: сравнивается время камеры); без EXIF используется порядок номеров файлов.

### Хранение

```
photo_meta    (photo_id, version, raw, meta, clip, thumb, taken_at, analyzed_at)  -- сырые детекции и производные метаданные
photo_faces   (id, photo_id, idx, embedding, px, doubtful, subject, source, score, level, cluster)
photo_flags   (photo_id, excluded, must_use, hero, best)                          -- решения фотографа
general_state (order_id, gallery)                                                 -- отпечаток портретной галереи
```

`photo_faces.source`: `auto` (связь пересчитывается), `manual` (выбрано фотографом), `stranger` (не из класса), `not_face` (ложное срабатывание). `level` автоматической связи: `auto` (используется макетом) или `uncertain` (показана на проверку, макетом не используется). Кластеры неопознанных лиц не хранятся отдельно: они пересчитываются, а решение по кластеру записывается в каждое его лицо.

Производные метаданные пересчитываются, когда меняется портретная галерея (отпечаток `general_state`) или версия анализа. Ручное решение по лицу пересчитывает только затронутые снимки.

## 4. Анализ кадра

1. **Техника:** размер, ориентация, экспозиция (среднее, доля пересвета и провалов), миниатюра 16×16 для сравнения кадров.
2. **Лица:** YuNet на кадре, уменьшенном до 2560 px (порог 0,6). Эмбеддинг SFace — по полноразмерному кадру для лиц от 24 px; опознание — от 40 px. Резкость — дисперсия лапласиана лица, уменьшенного до 64 px (у лиц меньше 64 px резкость не оценивается).
3. **Мимика:** сетка из 478 точек и 52 коэффициента MediaPipe: моргание левым и правым глазом, улыбка, поворот и наклон головы. Сетка с отрицательной уверенностью помечает лицо сомнительным, если его не подтверждает тело.
4. **Люди:** RTMO-s даёт рамки и точки тел. Лицо закрепляется за телом по точкам головы; повторное тело того же человека (сидящие друг за другом) отбрасывается. Число людей = тела + лица без тел.
5. **Сцена (CLIP):** теги из словаря (класс, библиотека, коридор, спортзал, сцена, праздник, студия, природа, море, город, пикник, зима), эстетика, постановка или репортаж, помещение или улица, эмбеддинг для поиска дублей. Эмбеддинги подсказок кешируются в `models/clip/prompts-*.json`.

### 4.1. Крупность

Для каждого человека — по самой нижней видимой в кадре группе точек тела:

| Значение | Признак |
|---|---|
| `detail` | людей нет |
| `close` | крупный: видны только плечи |
| `medium` | средний: видны бёдра или колени |
| `full` | в рост: видны щиколотки |
| `wide` | общий: щиколотки видны, но человек ниже 40 % высоты кадра |

Без тела крупность оценивается по высоте лица (≥18 % — крупный, ≥7 % — средний, ≥3,5 % — в рост). Крупность снимка — крупность самого крупного человека. При кадрировании в слот генератор пересчитывает **эффективную крупность** в пределах кропа: кадр «в рост», обрезанный по пояс, становится средним.

### 4.2. Брак

| Дефект | Когда | Уровень |
|---|---|---|
| `blur` | самое резкое из главных лиц (не меньше 60 % крупнейшего) нерезкое: < 120 | `reject` |
| `eyes_closed` | средний сигнал моргания ≥ 0,6, каждый глаз ≥ 0,45, голова не наклонена вниз | `reject` в постановочном кадре для главного лица, иначе `minor` |
| `exposure` | пересвет > 20 % или среднее < 0,12 | `warn` |
| `face_cut` | главное лицо касается края | `minor` |

Модель мимики не отличает закрытые глаза от взгляда вниз (на пикнике смотрят на еду), поэтому при наклоне головы вниз (`pitch < −0,25`) закрытые глаза не фиксируются, а в репортаже они только снижают оценку. `reject` убирает кадр из автоматического подбора, но не удаляет: фотограф видит его на вкладке «Брак».

Оценка качества 0–1: эстетика CLIP 45 %, резкость главных лиц 25 %, улыбка 20 %, минус штрафы за дефекты (каждый вид учитывается один раз).

### 4.3. Группы и зоны

- Число людей → `none`, `solo`, `pair`, `small_group` (3–6), `group` (7+), `class` (опознано ≥70 % класса либо людей не меньше 70 % класса и не меньше 7).
- `subject_box` — главные люди (не ниже половины самого высокого); `safe_box` — их головы с запасом. Кроп обязан сохранить `safe_box`.

### 4.4. Опознание

Галерея — эмбеддинги портретов персон заказа. В одном кадре связь один к одному: самые сильные пары назначаются первыми. Автоматическая связь — при сходстве ≥ 0,5 с отрывом ≥ 0,08 от следующей персоны (как у сортировки портретов); 0,42–0,5 — «проверить совпадение». Персона, уже связанная с лицом на этом снимке вручную, не предлагается другому лицу.

Неопознанные лица группируются лидерной кластеризацией при сходстве ≥ 0,55; два лица одного снимка никогда не попадают в одну группу. На примере SFace давала 0,6 разным похожим подросткам, поэтому пороги консервативны: лучше спросить фотографа, чем ошибиться.

## 5. Анализ съёмки

- **Серии:** соседние кадры (по времени ≤10 с или номерам ±2) с косинусом CLIP ≥ 0,92, без CLIP — по миниатюрам; любые кадры с косинусом ≥ 0,965 считаются дублями. Лучший кадр серии — выбранный фотографом, иначе годный с наибольшей оценкой; остальные помечаются как дубли и в автоматический подбор не попадают.
- **События:** разрыв во времени больше 20 минут начинает новое событие.
- **Покрытие:** сколько годных недублирующих снимков у каждой персоны.

## 6. Проверка фотографом (заказ → «Загрузка фотографий» → общая съёмка)

- **Все / Лучшие / Серии / Брак / Люди** (+ «В обработке», «Ошибки» при необходимости). На миниатюрах — группа, число людей, крупность, число опознанных учеников, брак, отметки.
- Действия над выделением: «Не использовать» / «Вернуть», «Обязательно», «Главное фото», «На обложку», «Удалить».
- **Серии:** кадры серии рядом, «Сделать лучшим».
- **Люди:** покрытие учеников (не найденные подсвечены), «Проверить совпадения» (лицо рядом с портретом кандидата), «Неопознанные люди» — группы похожих лиц; выбор ученика связывает все лица группы. Одиночные лица свёрнуты. Варианты: ученик, «Не из класса», «Это не лицо».
- **Подробнее:** снимок с рамками лиц, факты анализа и выбор человека для каждого лица.

API: `GET /api/orders/{id}/shoots/{shoot}/general`, `GET /api/orders/{id}/general/{photo}`, `PUT /api/orders/{id}/general/flags`, `PUT …/general/best`, `PUT …/general/faces`, `POST /api/orders/{id}/shoots/{shoot}/reanalyze`, миниатюра лица `GET /media/face/{face_id}/crop`.

## 7. Мастер-редактор

Фото-слой или ячейка коллажа с источником «Общее фото» хранит `pick`: категорию и кто должен быть на снимке.

```json
"pick": {"category": "few", "who": "hero"}
```

`who`: `hero` — герой разворота (ученик, которому посвящён личный разворот; только в разделах `repeat`), `owner` — владелец альбома, нет поля — любой.

Встроенные категории (`photo_pick.CATEGORIES`, в редакторе — `MasterPhotos`). Число людей считается от размера класса: «подгруппа» — от 4 человек до доли «весь класс».

| Категория | Фильтры | Если с героем снимков нет |
|---|---|---|
| `any` Любое | — | |
| `class` Весь класс | весь класс, постановка | |
| `subgroup` Подгруппа | 4+ человек, не весь класс, постановка | |
| `few` Вдвоём-втроём | 2–3 человека | репортаж с ним → дубль подгруппы |
| `solo` Один | 1 человек | крупный или средний репортаж → вдвоём-втроём → дубль подгруппы |
| `candid` Репортаж | репортаж | герой мелко → дубль подгруппы |
| `wide` Общий план | общий план | |
| `empty` Без людей | никого | |

Герой разворота должен быть одним из главных лиц кадра (не меньше 6 мм в печати и не меньше 60 % крупнейшего лица); мелко — только запасным шагом. «Дубль подгруппы» — не лучший кадр серии постановочной группы: лучший остаётся для общих разворотов, дубль берётся только в запасном шаге. После запасных шагов фильтры ослабляются по обычной очереди; в макете остаётся предупреждение о том, что взято вместо.

Категории можно менять и создавать свои в окне «Настройки альбома», вкладка «Категории фото». Документ хранит их в `photoCategories`: `[{id, name, people, scale, style, quality, tags}]`. Запись с id встроенной категории заменяет её фильтры и название (запасные шаги остаются), остальные — свои категории. Удалённая своя категория превращает свои слоты в «Любое». Слоты, сохранённые с прежними ролями (`role`, `buckets`, `include`), сервер понимает по-старому, а редактор при открытии переводит их в категории.

Документ хранит правила альбома `photoRules`: `reuse` (`album` / `section` / `allow`), `coverageMin` (0–10), `coverageMax` (0 — без предела), `rhythm`, `chronology`, `mixShoots` (снимки одного разворота из разных съёмок, если их несколько), `posedFirst` (в слотах без стиля постановочные ближе к началу раздела, репортаж — к концу). Сервер проверяет словари при сохранении и публикации.

Гибкий коллаж (`flex: {min, max}`, общий `pick`) создаёт по слоту на каждый возможный кадр. Слоты сверх минимума необязательные: они берут только снимок, подходящий без ослабления фильтров и запасных шагов, иначе кадр исчезает, а оставшиеся раскладываются по форме снимков. Снимок не повторяется в кадрах одного коллажа даже при разрешённых повторах.

Превью: `POST /api/master-templates/photo-preview` запускает настоящий подбор на синтетической съёмке (`test_shoot.py`: ~4 кадра на ученика, все группы и крупности, прогнанные через те же правила метаданных) для выбранного в тестовых данных владельца. Редактор рисует фигуры по рамкам людей, выделяет владельца и применяет возвращённое кадрирование; под ролью видно число подходящих тестовых снимков и ослабленные фильтры.

## 8. Генерация

1. Снимок заказа содержит `general` — компактные метаданные годных неисключённых снимков (включая дубли и брак с отметками) и прежний список `general_photos`.
2. Генератор раскладывает разделы и собирает слоты общих фото, не заполняя их. Слот без `include: owner` общий: один раз на весь альбом (у `with_item` — отдельно для каждого ученика разворота). Слот `include: owner` персональный: заполняется для каждого варианта из оставшихся снимков.
3. Кандидат должен: не быть дублем серии и браком; проходить фильтры; вмещать `safe_box` в пропорцию слота; давать не меньше 120 dpi; при `include` — лицо нужного ученика в печати не меньше 4 мм.
4. Порядок: слоты «главное фото», затем самые дефицитные, затем по порядку альбома. Оценка кандидата: качество, +1 обязательному, +0,35 «главному» в слоте героя, улыбка по роли, +0,25 за ученика ниже минимума появлений, −0,3 за ученика на максимуме, −0,6 за кадр той же серии и −0,15 за ту же крупность на развороте, −0,25 × отклонение от хронологии, −0,2 ниже 200 dpi. Равные оценки решает ID — результат воспроизводим.
5. Ослабление, если никто не подходит: качество → крупность → число людей → стиль → сцена → «кто на фото» → любая роль → обрезка людей → повтор. Ослабление «кто на фото», «любая роль», «обрезка» и «повтор» дают предупреждение в макете; ниже 200 dpi — тоже. Если общих фото нет совсем, каждый такой слот и кадр коллажа — ошибка.
6. Кадрирование: максимальный кроп пропорции слота, центр — на главных людях, `safe_box` внутри, над головами запас. Ручные `cropX/Y/Zoom` слоя общего фото не используются.
7. Отчёт `document.photo_report`: по каждому слоту число строгих кандидатов, ослабления и до 24 ранжированных снимков; покрытие учеников; обязательные снимки, не попавшие в макет. Предупреждение получает ученик, которого нет на общих фото альбома, и обязательный снимок без места.

Совместимость: слой `source: 'class'` без `pick` — роль `any`. Снимок заказа, сохранённый до анализа (без поля `general`), при ручных правках раскладывается точно как раньше — по кругу, заново для каждого варианта, с прежними отпечатками элементов, поэтому ручные замены не превращаются в конфликты. «Обновить из данных заказа» создаёт новый снимок, и общие фото подбираются по новым правилам.

## 9. Рабочий макет

При нажатии на рамку общего фото вкладка «Общие» показывает снимки, подходящие этому слоту, первыми и с отметкой «Подходит слоту». Вкладки «Групповые» (3+ человек), «Парные» и «Репортажные» заполняются по метаданным. Ручная замена сохраняется прежним механизмом `overrides`.

## 10. LLM (не реализовано)

Возможный следующий этап: только по выбору студии и с согласием родителей; отправлять лишь отобранные кадры в превью 512 px без имён; строгий JSON (описание сцены, «момент», неловкий кадр, подпись). Результат будет поправкой к оценке, а не основой: без LLM сервис работает полностью.

## 11. Калибровка и проверки

Пороги собраны в `general_meta.CONFIG` вместе с версией анализа `ga-1`. Их проверяли на 19 общих снимках `examples/real-photos` (крупные планы, группы, класс, пляж, библиотека, пикник): количество людей, крупность и теги совпали с визуальной оценкой; ложный брак от взгляда вниз и от размытого фона устранён. Опознание на этом наборе проверить нельзя: портреты примера — другие люди, поэтому все совпадения остались «на проверку». Точность опознания по классу нужно измерить на реальной съёмке студии с разметкой.

Тесты: `tests/test_general_meta.py` (крупность, группы, дубли тел, брак, опознание, кластеры, серии), `tests/test_photo_pick.py` (кроп, роли, персональные слоты, ослабления, обязательные, наследие, генерация и превью), `tests/test_general_photos.py` (очередь, связь с портретами, ручные решения при повторном анализе, исключения, ошибки анализа, очередь старых фото), `tests/test_master_templates.py` (валидация `pick`/`photoRules`), `tests/test_general_review_ui.js`, `tests/test_layout_photo_filter.js`.

## 12. Ограничения и следующие шаги

- Счётчик «Нужна проверка» заказа не учитывает неуверенные совпадения общих съёмок: они видны только на вкладке «Люди».
- Поворот головы и направление взгляда вычисляются, но в правилах ритма (взгляд внутрь разворота) пока не используются.
- Словарь сцен фиксирован; его нужно утвердить с фотографами.
- Выбор общих фото клиентом и учительский вариант с отдельными правилами подбора не реализованы.
- Оптимальное назначение внутри разворота (вместо жадного) — если качество подбора потребует.
