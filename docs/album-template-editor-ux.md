# Редактор дизайнов альбома для фотографа — UX-спецификация

26 сентября 2026 · UX-направление развития. Реализованные функции и ограничения: [редактор мастер-макета](master-editor.md). Возможности ниже, не перечисленные в этом отчёте, остаются целевыми.

## Решение и границы

Фотограф создаёт в своём кабинете **многоразовый дизайн альбома**: обложку, набор шаблонов разворотов, правила подстановки данных и допустимые варианты композиции. Затем он выпускает **издание** с форматом и параметрами печати и выбирает его для заказов. В заказе фотограф работает с **макетом класса**: подставляет конкретные фотографии, кадрирует, проверяет и публикует результат клиентам. Эти редакторы должны использовать одну модель элементов и один механизм рендера, но иметь разные права на изменения.

Дизайны и издания теперь создаёт фотограф в своей студии. Редактор заказа отделён от мастер-макета; публикация новой версии не меняет уже созданные заказы.

**Цель первой версии:** фотограф может перенести один типовой альбом, настроить динамические поля и использовать его для нового заказа без правки JSON или серверного кода. Интерфейс напоминает Figma расположением панелей и прямым редактированием на холсте, но основные действия названы терминами альбома и печати.

## Что подтверждено исследованием

- В Figma понятная пространственная схема: слева страницы/слои/компоненты, в центре холст с масштабированием и перемещением, справа свойства выделенного объекта, инструменты создания под рукой. Для фотографа эту схему стоит сохранить, заменив «страницы» на «обложка / разделы / развороты», а «компоненты» — на библиотеку блоков альбома. [Справка Figma о навигации](https://help.figma.com/hc/en-us/articles/30925881896727-FD4B-Navigate-Figma-Design-files), [свойства и слои](https://help.figma.com/hc/en-us/articles/360039956914-Adjust-alignment-rotation-position-and-dimensions).
- В InDesign пакет для передачи включает исходный документ, связанные изображения, сведения о шрифтах, опционально IDML и контрольный PDF. Значит, импорт нужно проектировать как **пакет с эталонным PDF**, а не как одиночный `.indd`. [Adobe: Package](https://helpx.adobe.com/uk/indesign/desktop/print/preflight/package-files-for-output.html).
- IDML — формат обмена InDesign; его можно экспортировать из приложения. Для первой итерации это более явная входная точка конвертера, чем обещание универсально прочитать `.indd`. Набор поддерживаемых свойств нужно проверить на реальных файлах. [Adobe: IDML](https://helpx.adobe.com/indesign/desktop/troubleshoot/file-and-output-issues/unable-to-export-pdf.html).
- PSD сохраняет слои, эффекты и маски, но наличие слоёв **не означает**, что каждый эффект удастся превратить в редактируемый элемент нашего редактора. Для сложных слоёв нужен режим изображения с видимым предупреждением. [Adobe: форматы Photoshop](https://helpx.adobe.com/photoshop/desktop/save-and-export/export-files-to-different-formats/photoshop-file-formats-overview.html), [Smart Objects](https://helpx.adobe.com/photoshop/desktop/create-manage-layers/smart-objects/smart-objects-overview-and-benefits.html).
- Для печатного макета нужны проверки недостающих шрифтов и ссылок, переполнения текста и разрешения изображений; Adobe показывает их в Preflight. Система должна привязывать каждую проблему к элементу и предложить действие. [Adobe: Preflight](https://helpx.adobe.com/au/indesign/desktop/print/preflight/configure-and-use-the-preflight-panel.html).

Выводы о нашем продукте ниже — проектные решения, а не заявленные возможности Figma или Adobe. Исследование основано на документации и текущем коде; наблюдений за фотографами пока не было.

## Основные сценарии

1. **Создать с нуля.** Кабинет → «Мои дизайны» → «Новый дизайн» → формат/тип обложки/типография → пустая обложка и базовые развороты → элементы и динамические слоты → проверка на тестовом классе → «Выпустить издание».
2. **Перенести из InDesign.** «Импортировать» → выбрать пакет с IDML, связями и эталонным PDF → отчёт о страницах, шрифтах, потерянных связях и неподдержанных свойствах → сравнить исходник и конвертацию → назначить переменные поля и повторяемые блоки → проверить тестовые составы → выпустить.
3. **Перенести из Photoshop.** Выбрать PSD и эталонный PDF/PNG → увидеть слои → отметить заменяемые фото и текст → сохранить сложные эффекты как статичные изображения или вручную собрать из поддерживаемых элементов → сравнить → проверить → выпустить. Поддержку PSB исследовать отдельно на реальных больших файлах.
4. **Использовать в заказе.** Выбрать издание → заполнить класс → «Создать макет» → проверить все варианты → сделать разрешённые локальные правки → опубликовать клиенту. Издание остаётся закреплённым за заказом.
5. **Обновить дизайн.** Создать новую черновую версию из опубликованной. После выпуска она доступна новым заказам; существующие заказы сохраняют прежнюю версию. Перевод заказа на новую версию — отдельное действие с предварительным сравнением и проверкой несовместимых правок.

## Экран редактора

```text
┌ Мои дизайны / Название · Черновик ─── Отменить / Вернуть ─── Проверить ─ Выпустить ┐
│ ЛЕВАЯ ПАНЕЛЬ              │ ХОЛСТ: обложка или разворот            │ ПРАВАЯ ПАНЕЛЬ │
│ Структура                 │ линейки · вылет · обрез · безопасная   │ Свойства      │
│  Обложка                  │ область · корешок · сетка              │  Геометрия    │
│  Вступление               │ [визуальные элементы и фото-слоты]    │  Вид          │
│  Персональный разворот    │                                        │  Данные       │
│  Класс / Учителя / Финал  │  Масштаб, рука, выделение, направляющие│  Печать       │
│ Слои / Библиотека         │                                        │               │
├───────────────────────────┴────────────────────────────────────────┴───────────────┤
│ Тестовые данные: 3 / 20 / 54 ученика · 0 / 1 / 10 / 24 учителя · вариант ученика   │
│ Ошибки и предупреждения: 3  → переход к конкретному слою                          │
└────────────────────────────────────────────────────────────────────────────────────┘
```

- **Левая панель:** структура издания, миниатюры, иерархия слоёв выбранного шаблона, поиск слоя, библиотека готовых блоков. Общие и персональные шаблоны различаются меткой.
- **Центр:** реальная геометрия страниц в миллиметрах; масштаб, панорама, выделение, прямое изменение размера и позиции, направляющие, привязки, линейки, режимы «макет / данные / печать».
- **Правая панель:** свойства выделения; при отсутствии выделения — свойства страницы и издания. Секции открываются по типу элемента, а недоступные настройки имеют объяснение.
- **Верх:** имя дизайна и версия, статус сохранения, история, предпросмотр на тестовых данных, проверка и выпуск. Сохранение черновика автоматическое; выпуск — отдельное действие.
- **Низ:** переключатель тестового состава и варианта, список проблем. Замена тестовых данных не меняет дизайн.

## Каталог элементов первой версии

| Элемент | Что редактируется | Связь с данными |
|---|---|---|
| Страница / разворот / обложка | формат, поля, вылет, фон, сетка, корешок | роль шаблона: общий, персональный, учительский |
| Фото-рамка | положение, размер, форма прямоугольник/эллипс, обрезка, заполнение, кадрирование | портрет ученика/учителя, альтернативный портрет, общее фото, фото класса, фото группы |
| Текстовый блок | положение, размер, шрифт, начертание, межстрочный интервал, выравнивание, цвет | имя, фамилия, цитата, класс, школа, год, предмет, подпись фотографа; фиксированный текст |
| Фигура | прямоугольник, эллипс, линия; заливка, обводка, прозрачность | статичная декорация или фон |
| Изображение / декор | размещение SVG/PNG/JPEG, масштаб, обрезка | статичный ресурс дизайна; не заменяется клиентом |
| Группа | вложенность, блокировка, видимость, порядок слоёв | нет; совместное позиционирование |
| Повторяемая карточка | рамка фото + имя + опциональный текст; сетка, интервалы, порядок | список учеников или учителей с правилом переполнения |
| Компонент | повторное использование группы в шаблонах, локальные разрешённые свойства | идентичность оформления; может содержать слоты |

**Для следующей очереди:** произвольные векторные кривые, сложные маски/эффекты, многостолбцовый текст, обтекание, смешивание слоёв, ручной кернинг каждого символа. Их поддержка зависит от проверенных реальных файлов и движка PDF; до этого импорт показывает статичный слой или требует упрощения.

## Свойства и действия

**Общие операции:** выбрать один/несколько слоёв, создать, дублировать, копировать/вставить, удалить, сгруппировать, блокировать, скрыть, переименовать, изменить порядок, выровнять, распределить, переместить клавишами, отменить/вернуть, увидеть историю. Перемещение и изменение размера задаются мышью и числами в миллиметрах. Есть масштаб «по странице / по развороту / 100%», пробел для панорамы, контекстное меню и подсказка горячих клавиш.

**Фото:** назначить роль, выбрать допустимый источник и владельца, задать заполнение/вписывание и начальную точку кадра; обязательность, запасное фото, поведение пустого слота. В редакторе заказа содержимое слота заменяется и кадрируется без изменения его геометрии, если шаблон не разрешает иное.

**Текст:** фиксированный текст или переменная; примерные данные прямо на холсте; длина/перенос/уменьшение кегля до минимума; предупреждение о переполнении вместо скрытого обрезания. Права на изменение в заказе задаются автором: нельзя, фотограф, клиентское поле анкеты.

**Повторение и варианты:** роли разделов; шаблон на 3, 8, 20, 30, 54 учеников и 0, 1, 10, 24 учителей как проверяемые состояния, а не отдельные нарисованные альбомы. Для карточек задаются диапазон вместимости, сетка, порядок, добавление страниц и поведение последней неполной страницы. Персонализация обложки и разворота задаётся явно. Все варианты одного заказа получают одинаковое число разворотов согласно текущему правилу продукта.

**Печать:** размер страницы и обложки, корешок, линия реза, вылет, безопасная область, профили цвета/требования типографии, минимальное разрешение; проверка соответствия PDF выбранной спецификации. Профиль печати закрепляется в издании и не меняется отдельно для каждого заказа.

## Импорт: обещания интерфейса и обработка исключений

Первый экран импорта предлагает **«Из InDesign (IDML + связи + PDF)»**, **«Из Photoshop (PSD + эталон)»** и **«Из PDF как подложки»**. Последний вариант сохраняет вид, но изначально не даёт редактируемых слоёв; поверх него можно расставить новые фото- и текстовые слоты. Это полезный путь для быстрого переноса, но статус «подложка» должен быть виден.

После загрузки показывается отчёт по каждой странице и слою: «редактируется», «импортирован как изображение», «требует шрифт», «ссылка отсутствует», «не удалось перенести». Для каждого различия между эталоном и результатом есть миниатюра и переход к элементу. Нельзя называть импорт успешным только потому, что файл открылся. Порог допустимого визуального расхождения следует определить на наборе реальных макетов.

**Порядок реализации импорта:** (1) PDF-подложка и ручная разметка слотов; (2) IDML с базовой геометрией, текстовыми и графическими рамками, ссылками; (3) PSD с базовыми слоями; (4) расширение совместимости по статистике конкретных неподдержанных свойств. `.indd` как прямой вход не обещать до отдельной проверки конвертера. Импортированный исходник и отчёт хранятся отдельно от нормализованного документа.

Шрифты нельзя автоматически переносить из любого пакета и применять как шаблонные без проверки лицензии; UI предлагает выбрать доступный шрифт или загрузить разрешённый. [Adobe Fonts о пакетировании и лицензиях](https://helpx.adobe.com/fonts/web/getting-and-using-fonts/package-font-files.html).

## Проверка и выпуск

Проверка работает на эталонных составах, включая крайние значения объявленной ёмкости, длинные имена и цитаты, отсутствие необязательных фото, учительский вариант и разные количества учителей. Она показывает:

- ошибки структуры: обязательный слот без роли, отсутствующий шаблон раздела, невозможная ёмкость, разное число разворотов вариантов;
- ошибки содержимого: переполнение текста, отсутствующий шрифт/файл, недопустимое фото в роли, пустой обязательный слот;
- ошибки печати: выход важного текста за безопасную область, нехватка вылета, недостаточное разрешение, несовпадение размера/корешка/цветовых требований;
- различия импорта: переведённые в изображение слои, замены шрифтов, видимые расхождения с эталоном.

Каждая строка содержит причину, затронутые варианты и действие «Показать на холсте». Ошибки блокируют выпуск; предупреждения требуют просмотра. Выпуск создаёт **неизменяемую версию издания**. Черновик можно продолжать как следующую версию. Перед выпуском фотограф видит формат, диапазон класса, число шаблонов, результаты проверки и контрольный PDF для нескольких составов. PDF/X и другие печатные профили выбираются по требованиям типографии, а не по универсальному значению по умолчанию. [Adobe: экспорт PDF для печати](https://helpx.adobe.com/indesign/desktop/save-export-and-publish/save-and-export/export-pdfs-for-printing.html).

## Приоритет реализации

### Основа на открытом ПО

Реализованный холст построен на Fabric.js 6.7.1. Канонический документ хранится в собственной модели с миллиметрами, источниками данных и версиями. Fabric.js отвечает за взаимодействие с объектами; его сериализация не заменяет документ программы альбома.

Альтернатива для пилота — **Konva** (MIT): мощная сцена и трансформации, но встроенного редактирования текста прямо на холсте нет, рекомендован HTML `textarea` поверх холста. Это увеличит объём текстового UX. [Konva: проект](https://github.com/konvajs/konva), [текст](https://konvajs.org/docs/sandbox/Editable_Text.html).

**Penpot** — полноценный открытый редактор (MPL-2.0), но встраивание его целиком означало бы принять отдельную дизайн-систему и инфраструктуру, а затем связать её с нашей моделью издания и PDF. Его разумнее изучить как внешний инструмент для дизайна, чем форкать для кабинета. [Penpot: исходники и лицензия](https://github.com/penpot/penpot).

Для PSD можно прототипировать импорт на **ag-psd** (MIT), но библиотека заявляет ограничения по цветовым режимам, тексту и отсутствие поддержки PSB. Нужны реальные файлы фотографов и отчёт о том, что было преобразовано. [ag-psd: возможности и ограничения](https://github.com/Agamnentzar/ag-psd), [лицензия](https://github.com/Agamnentzar/ag-psd/blob/master/LICENSE).

В обоих вариантах движок холста не заменяет наш генератор вариантов, проверки ёмкости, импорт IDML/PSD, печатный PDF и версионирование. Текущий [рендер PDF](../album_factory/layout_render.py) работает через ReportLab; соответствие холста и PDF нужно доказывать на контрольных разворотах, прежде чем расширять набор поддерживаемых эффектов.

**Этап A — основа редактора.** «Мои дизайны», создание черновика, холст, обложка/развороты, слои, рамки фото, текст, фигуры, декор, геометрия в мм, роли данных, предпросмотр на примерах, история/автосохранение, проверка, выпуск. Итог: один дизайн можно создать без JSON.

**Этап B — перенос существующих работ.** PDF-подложка с разметкой заменяемых слотов; затем IDML и PSD-конвертеры с отчётом и сравнением. Итог: фотограф понимает, что сохранилось и что нужно исправить, до использования дизайна в заказе.

**Следующее расширение автоматизации.** Повторяемые карточки, адаптивная вместимость и новые версии уже реализованы. Компоненты, несколько форматов и контролируемая миграция заказов остаются следующими задачами.

**Отдельный редактор заказа** использует выпущенное издание: фото, кадр, разрешённый текст, порядок в заданных рамках, проверка и публикация. Он не меняет мастер-шаблон.

## UX-исследование перед фиксацией объёма

Провести 5–8 наблюдаемых сессий с фотографами, которые реально собирают выпускные альбомы; включить работающих в InDesign, Photoshop и обоих инструментах. Попросить каждого принести обезличенный типовой файл и выполнить задачи: импорт, назначение портрета и имени, изменение общей композиции, проверка класса с другим числом учеников, поиск ошибки и выпуск. Измерять завершение без помощи, время, возвраты, ошибки назначения роли и расхождения с исходником. Собрать частоты элементов/эффектов в их файлах. После 3–4 сессий уточнить прототип, затем проверить его на остальных. Нельзя считать документационный обзор заменой этого исследования.

## Критерии готовности первой рабочей версии

1. Фотограф создаёт, сохраняет, дублирует и выпускает дизайн из кабинета без ручной правки JSON.
2. Можно сделать обложку, персональный и общий развороты, назначить портрет, имя, класс и общее фото; увидеть результат минимум на двух составах класса.
3. Любая правка имеет отмену; опубликованное издание и ранее созданный заказ не меняются при редактировании черновика.
4. Проверка указывает конкретный слой и вариант; блокирующая ошибка не позволяет выпустить издание.
5. Контрольный PDF визуально совпадает с холстом по положению, размерам, кадрированию и переносам текста в согласованных тестовых случаях.
6. Импорт показывает статус каждого слоя и эталон для сравнения; неподдержанная возможность никогда не исчезает молча.
