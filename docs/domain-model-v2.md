# Сущности и автовёрстка Album Factory — версия 2

Редакция от 24 сентября 2026. Документ заменяет в [domain-model.md](domain-model.md) каталог (продукт, пакет, сценарий, «конфигурация сценария»), выбор фото и раздел о генерации и макетах. Остальные правила версии 1 действуют без изменений: доступ по ссылке и двум PIN, распределение экземпляров, получение, согласование, разрешение производства, правка согласованного макета. Это целевая модель; реализован только прототип генератора, описанный в разделе 8.

## 1. Принятые решения

1. **Каталог разделён по владельцам.** Дизайн и издание делает команда сервиса; фотограф выбирает издание и задаёт своё предложение с ценой. Сущности «продукт фотографа», «версия пакета», «версия сценария» и «конфигурация сценария» сливаются в издание и предложение.
2. **Число разворотов зависит от размера класса** в пределах диапазона издания. Внутри одного заказа все варианты имеют одинаковое число разворотов.
3. **Персонализация в MVP:** обложка, персональный разворот и порядок разворотов (ученик видит свой разворот класса первым).
4. **Групповые фото конкретных учеников в MVP не подбираются автоматически.** Входные фото альбома — портреты, выбранные клиентом, и общие фото, выбранные фотографом.
5. **Шаблоны и макеты хранятся как документы (JSON)**, а не как отдельные строки базы на каждый слой. Реляционные таблицы — только для ссылок, статусов и поиска.
6. **Ограничения анкеты выводятся из издания.** Допустимая длина цитаты — минимальная из вместимостей всех слотов, где она выводится.

## 2. Словарь

Одно понятие — одно слово. Слово «пакет» в продуктовом смысле больше не используется.

| Внутреннее имя | В интерфейсе фотографа | Смысл |
|---|---|---|
| `Design` | Дизайн | Визуальная серия, например «Классика» |
| `AlbumEdition` | не показывается отдельно | Неизменяемая программа сборки альбома в одном дизайне и формате |
| `Offer` | Комплектация | Предложение фотографа: название, цена, ссылка на издание |
| `SpreadTemplate` | — | Заготовка разворота или обложки со слоями и слотами |
| `Section` | — | Часть альбома: вступление, персональный разворот, учителя, класс |
| `LayoutState` | — | Подготовленная автором композиция для диапазона количества людей |
| `Layout` | Альбом класса | Рабочий результат генерации с правками фотографа |
| `AlbumVariant` | Вариант | Последовательность разворотов для одного ученика или учителя |
| `LayoutRevision` | Редакция | Неизменяемый снимок альбома класса со всеми вариантами |
| `LayoutOverride` | Правка | Решение фотографа поверх генерации |

## 3. Каталог

**Дизайн (`Design`).** Название, превью, набор шаблонов. Принадлежит сервису. Позднее — дизайны, переведённые из PSD фотографа за отдельную плату.

**Издание (`AlbumEdition`).** Неизменяемая опубликованная версия:
- дизайн, формат страницы, тип обложки;
- диапазон разворотов (`spreads.min`–`spreads.max`); он должен входить в числа разворотов, которые принимает типография;
- ёмкость: сколько учеников и учителей помещается (`capacity`);
- поддержка учительского варианта;
- роли фото (`photo_roles`) — кто выбирает фото для каждой роли;
- спецификация печати, включая формулу корешка;
- разделы и точные версии шаблонов.

Издание публикуется только после двух проверок: матрица ёмкости (каждое количество учеников и учителей в объявленном диапазоне планируется без ошибок) и проверка граничных текстов.

**Предложение фотографа (`Offer`).** Название («Стандарт»), ссылка на издание, внутренняя цена, активность. Отдельно не версионируется: заказ копирует название и цену на момент создания.

**Заказ** хранит ссылку на версию издания и копию предложения. Изменение каталога не меняет существующие заказы.

Соответствие версии 1:

| Версия 1 | Версия 2 |
|---|---|
| Продукт фотографа (`AlbumProduct`) | Дизайн (сервис) + группа предложений фотографа |
| Пакет (`PackageVersion`): цена | Предложение (`Offer`) |
| Пакет: число разворотов, обложка, возможности | Издание (`AlbumEdition`) |
| Сценарий (`AlbumRecipeVersion`) и его «конфигурация» | Издание (`AlbumEdition`) |
| Шаблон (`LayoutTemplateVersion`), элементы, слоты, состояния | Шаблон разворота внутри издания, JSON-документ |

## 4. Содержимое заказа

Ученики, учителя заказа, съёмки и фото — как в версии 1. Изменения:

- **Выбор фото по роли (`PhotoSelection`):** владелец, роль, фото. Владельцы: `student:<id>`, `teacher:<id>`, `order` (общие фото), `teacher_variant`. Роли объявляет издание, например `main_portrait` (выбирает клиент), `class_photo`, `group_photo` и `teacher_variant_photo` (выбирает фотограф). `PortraitSelection` версии 1 — частный случай с ролью `main_portrait`.
- **Рамка лица.** Автокадрирование использует рамку лица из сортировки. Сейчас `FaceEngine.extract` возвращает только вектор; нужно сохранять нормализованную рамку `[x, y, w, h]` в метаданных версии фото.
- **Ограничения анкеты** берутся из издания (`field_limits`). В текущем коде расхождение: кабинет клиента разрешает цитату до 300 символов, а ядро PDF — до 180.
- **Портрет учителя в справочнике** — отдельная копия файла, принадлежащая справочнику школы, со своим сроком хранения. Файлы заказа удаляются по правилам хранения заказа и не должны ломать справочник.

## 5. Альбом класса и варианты

- **Снимок входных данных** — канонический JSON (ученики в стабильном порядке, учителя, выборы, тексты, метаданные фото) и его хеш.
- **Запуск генерации** — версия издания, хеш входа, документ, проблемы. Одинаковый вход даёт побайтно одинаковый документ.
- **Рабочий альбом класса** — запуск генерации плюс упорядоченный список правок. Итог = генерация с применёнными правками.
- **Документ альбома** хранит общие развороты (`shared_spreads`) один раз, персональные развороты и обложки по владельцам, последовательность разворотов каждого варианта, план разделов, проблемы и хеш редакции.
- **Вариант** не хранится как отдельный альбом: это последовательность ссылок на общие и персональные развороты.
- **Редакция** — неизменяемый итоговый документ и его хеш. Публикация и согласование ссылаются на редакцию.

Из версии 1 убраны отдельные таблицы `LayoutPage`, `LayoutSpread`, `LayoutElement`, `ContentBinding` и «страница, добавленная фотографом»: при одинаковом числе разворотов добавление страницы в один вариант невозможно. Вместо этого позднее — замена шаблона разворота на другой, разрешённый изданием в этой позиции.

## 6. Как работает генератор

Генерация — чистая функция `документ = generate(издание, снимок)`, затем `apply(правки)`.

### 6.1 Разделы

- `page` — один разворот с данными заказа (вступление, финальный разворот). Может требовать фото (`requires`); без него обязательный раздел — ошибка, необязательный пропускается.
- `per_variant` — персональный разворот: по экземпляру на каждого владельца варианта, свой шаблон для ученика и для учительского варианта.
- `flow` — сетка учеников или учителей с подготовленными состояниями.
- `fill_to_min` — необязательный разворот, который добавляется, только если без него не набирается минимум разворотов.

### 6.2 Планирование разворотов

Для раздела `flow` с N людьми берётся минимальное k от `ceil(N / максимальная вместимость)`, при котором N делится на k разворотов поровну (`floor(N/k)` и `ceil(N/k)`) и для каждой доли есть состояние. Поэтому 10 учителей дают 5 + 5, а не 9 + 1; 19 учеников при вместимости 18 — 10 + 9.

Если сумма меньше минимума издания, сначала добавляются разделы `fill_to_min`, затем растягиваются разделы с флагом `expandable`, если это допускают состояния. Если сумма больше максимума или класс вне ёмкости — ясная ошибка до вёрстки: «Издание рассчитано на 3–54 учеников, в заказе 60».

### 6.3 Состояния и ячейки

Состояние задаёт диапазон количества и блоки — отдельные сетки на левой и правой странице, чтобы лица не попадали в корешок. Люди распределяются по блокам с большей долей первой (11 → 6 + 5). Внутри блока заполнение по строкам; неполная последняя строка и неполная сетка центрируются. Элементы ячейки заданы в долях ячейки и масштабируются вместе с ней.

### 6.4 Привязки

- Текст: `{order.year}`, `{item.name}`, `{variant.quote}`. `item` доступен только в ячейке сетки, `variant` — только в персональных разворотах и на обложке; общий разворот не может ссылаться на владельца варианта.
- Фото: `item.photo:main_portrait`, `order.photo:class_photo`; список означает запасные варианты по порядку.
- Необязательный элемент с пустыми данными не выводится (нет цитаты — нет кавычек).

### 6.5 Стабильные ключи и правки

Каждый элемент получает смысловой ключ, не зависящий от номера разворота и позиции:
- `students/cell[student:S17]/portrait` — портрет в сетке класса;
- `personal[student:S17]/quote` — цитата на персональном развороте;
- `cover[student:S17]/name`, `intro/title`, `teachers#0/title`.

Правка хранит ключ, тип, значение и исходное значение генерации (`base`). Типы: `photo`, `crop`, `text`, `hide`. При перегенерации:
- ключ есть и исходное значение то же — правка применяется, даже если сетка сменила состояние;
- данные изменились (ученик выбрал другое фото) — конфликт `base_changed`;
- элемента больше нет (ученик удалён) — конфликт `missing`;
- кадр сделан для другого фото — конфликт `photo_changed`.

Конфликты показываются фотографу; молча они не применяются.

### 6.6 Кадрирование и текст

Фото заполняет слот с сохранением пропорций. При наличии рамки лица её высота занимает долю `face_scale` высоты слота, глаза находятся на линии `eye_line`, кадр сдвигается к границе снимка, но не выходит за неё. Без рамки — кадр по центру.

Текст подбирается от `size` до `min_size` шагом 0,5 pt теми же метриками, которыми рисуется PDF. Не помещается — ошибка, обрезки нет.

### 6.7 Проверки

- Ошибки (блокируют экспорт): пустой обязательный слот, разрешение ниже `hard_min_dpi`, переполнение текста, отсутствующие в шрифте символы.
- Предупреждения: разрешение ниже `min_dpi`, текст длиннее лимита анкеты, текст вне безопасной зоны или через корешок.

### 6.8 Обложка и экспорт

Корешок = `base_mm + per_spread_mm × число разворотов`, поэтому ширина обложки считается после планирования. Элементы обложки привязаны к панелям `back`, `spine`, `front`.

PDF варианта: обложка и развороты в порядке варианта. Обработанные кадры кешируются между вариантами. Позднее общие развороты стоит рендерить один раз и склеивать PDF из готовых страниц.

## 7. Продуктовые следствия

- **Изменение состава класса после публикации** может изменить число разворотов, ширину корешка и все варианты. Это изменение макета: действует повторное согласование из версии 1 (§6).
- **Ёмкость издания видна при создании заказа.** При закрытии сбора — предупреждение, если класс вышел за пределы.
- **В переставляемых разделах нет элементов «только на первом развороте»:** после перестановки первым может оказаться любой разворот. Генератор отклоняет такое издание.
- **Запасное фото должно подходить по пропорциям.** Горизонтальное фото класса в вертикальном слоте портрета выглядит плохо, поэтому у учительского разворота свой горизонтальный слот. Проверку совместимости пропорций запасных привязок стоит добавить в публикацию издания.
- **Типография.** Диапазон разворотов издания должен входить в допустимые числа разворотов выбранного переплёта.
- **Канал замечаний.** Согласует один ответственный, но проверить 30 вариантов он не может. Рекомендуется позволить родителю оставить замечание к своему варианту (без клиентского редактора). Решение не принято.
- **Метрика автовёрстки** — доля разворотов без правок фотографа и минуты правки на заказ; считается по списку правок.

## 8. Прототип

- `album_factory/layout_engine.py` — планирование, привязки, кадрирование по лицу, подбор текста, стабильные ключи, правки и конфликты, проверки, матрица ёмкости (`capacity_matrix`), ограничения анкеты (`field_limits`).
- `album_factory/layout_render.py` — PDF варианта из документа с кешем кадров; экспорт блокируется при ошибках.
- `examples/editions/classic-v1.json` — издание «Классика»: 5–8 разворотов, 3–54 ученика, 0–24 учителя, учительский вариант.
- `scripts/layout_demo.py` — демонстрационный класс из пронумерованных тестовых карточек (без изображений людей) с меткой «лица»: `.venv/bin/python scripts/layout_demo.py --students 30 --teachers 10`. Результат — `output/layout-demo/document.json` и PDF.
- `tests/test_layout_engine.py` — балансировка, число разворотов, порядок в вариантах, правки и конфликты, кадрирование, ограничения анкеты, сквозной PDF (с `ALBUM_TEST_FONT`).

Ограничения прототипа: контрольный RGB PDF без вылетов, ICC и PDF/X; нет превью PNG, редактора, хранения в базе и связи с сервером; рамка лица берётся из снимка, а не из сортировки; нет проверки пропорций запасных привязок; шаблоны пишутся вручную в JSON.

## 9. Открытые вопросы

- Как цена предложения зависит от числа разворотов: фиксированная цена, таблица цен по числу разворотов или доплата за разворот.
- Формат подготовки шаблонов командой: вероятно, Figma с соглашением об именах слоёв (`slot:photo:main_portrait`, `state:t5_8`) и внутренний конвертер в JSON.
- Граница частичной перегенерации: какие изменения данных запускают её автоматически, а какие — только по команде фотографа.
- Канал замечаний родителей к своему варианту.
- Перечень допустимых чисел разворотов у первой типографии.

## 10. Влияние на план разработки

- **M04:** схема хранит издания, предложения, выборы по ролям и документы альбома вместо таблиц элементов.
- **M19:** модель издания и шаблонов по разделам 3 и 6; прототип покрывает основу.
- **M20:** генерация по разделу 6; прототип покрывает планирование, варианты и правки, без хранения и интерфейса.
- **M35:** каталог фотографа — предложения со ссылкой на издание.
- **M14 / сортировка:** сохранять рамку лица для автокадрирования.
- **M16:** лимиты анкеты из издания.
