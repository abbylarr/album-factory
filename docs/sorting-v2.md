# Проба сортировки V1 / V2 / V3

Откройте `/sorting-lab` или «Проба сортировки V1 / V2 / V3» в боковом меню любого интерфейса. Выберите заказ, диапазон и алгоритм; «Сравнить все четыре» запускает четыре независимых прохода; «Сравнить V2 серии и V3» — два. Кнопки над результатом переключают пробные группы. Отчёт можно скачать; ссылка с идентификатором пробы открывает сохранённый результат после перезапуска сервера.

Это отдельная лаборатория, а не переключение рабочего алгоритма заказа. Она не меняет фотографии, персоны, имена, ручные переносы и текущий обработчик. Результаты лежат отдельно в `data/sorting_trials`. Рабочая обработка использует V3. Автоматического применения экспериментальных групп нет.

## Варианты

- **V1:** прежний способ чтения через Pillow, YuNet + SFace для каждого снимка, прежние пороги группировки.
- **V2 / быстрое чтение:** декодирование JPEG через OpenCV с уменьшением 2/4/8, когда остаётся не менее 1600 пикселей по длинной стороне. Полное распознавание каждого снимка. Если быстрый проход не дал вектор лица, повторяется исходное чтение и распознавание. При успешном распознавании пиксели и вектор могут отличаться от V1; полная идентичность результатов не гарантируется.
- **V2 / серии:** быстрое чтение плюс числовой порядок имён. Обрабатываются крайние кадры тройки; средний допускается пропустить, только если крайние уверенно назначены одной персоне, префиксы совпадают, каждый числовой разрыв не превышает 3, пропорции превью близки, а RMS-разница каждого соседнего превью со средним меньше 0,065. Это начальные экспериментальные пороги, не оценка вероятности. Все назначения по серии помечаются `uncertain`, имеют `source=sequence` и ссылки на два опорных кадра. Они никогда не попадают в набор образцов лиц и не становятся опорными кадрами. Каждое реально распознанное лицо сравнивается со всеми найденными персонами, поэтому повторное появление человека не ограничено текущей серией.

Номер файла и сходство превью не доказывают личность. Случай А–Б–А может пройти эвристику; групповой кадр в середине также может быть пропущен. Поэтому режим серий остаётся пробным, а предположения видны отдельно. EXIF-время и идентификатор камеры в этой версии не используются: в доступных рабочих JPEG эти данные отсутствуют. Смешанные камеры/папки и сброшенная нумерация не подходят для доверенного назначения по серии.

## Как читать сравнение

Проба выбирает непрерывный диапазон в числовом порядке файлов. V1 и V2 без серий обрабатывают выбранные снимки в исходном порядке добавления; серии — в числовом порядке с опережающей обработкой опорных кадров. Начальные группы пусты в каждом проходе; ручные производственные назначения не используются. Изменение порядка может само по себе изменить жадную группировку.

Сравнение не зависит от номеров групп: считаются пары фотографий, объединённые или разделённые относительно V1, и снимки с изменившимся составом группы/статусом. Это **согласие с V1**, а не точность по ручной разметке. Изменения флага неуверенности не входят в число расхождений состава; предположенные снимки отмечены отдельно.

Время включает чтение, распознавание, сопоставление и проверки превью, но не загрузку, создание превью, запуск модели и запись производственных групп в SQLite. Все варианты держат образцы лиц в памяти. Поэтому V1 воспроизводит алгоритм, но не измеряет накладные расходы повторных SQL-запросов рабочего обработчика. Проходы идут последовательно V1 → V2 → серии; ОС может кешировать файлы. Один замер не является гарантией пропускной способности.

Проба запускается только после опустошения рабочей очереди и занимает общий обработчик до завершения. Новые загрузки в это время могут ждать. Перезапуск сервера прерывает незавершённую пробу; готовые отчёты сохраняются. При удалении исходных снимков их превью в старых отчётах станут недоступны.

## Отдельный скрипт

```sh
.venv/bin/python scripts/benchmark_sorting_v2.py \
  --order ORDER_ID --limit 120 --offset 0 \
  --output output/sorting-trial.json
```

`--mode compare|compare_v3|v1|v2|v2_series|v3`, `--data PATH`. Скрипт открывает SQLite только для чтения и проверяет неизменность назначений до/после пробы. Не запускайте его параллельно с обработкой для воспроизводимого замера. API и браузерный интерфейс сериализуют пробы автоматически внутри одного процесса сервера.

## V3: параллельная подготовка

V3 использует тот же порядок опорных кадров, те же пороги, ту же модель и те же правила серий, что V2 / серии. Два дополнительных потока читают JPEG и уменьшают его до 1600 пикселей по длинной стороне, пока основной поток распознаёт текущий кадр. Очередь ограничена тремя подготовленными изображениями; весь заказ не загружается в память. Пиксели перед моделью проверены на идентичность пути V2. Модель остаётся в одном потоке.

Подготовка опережает распознавание, поэтому может прочитать и кадр, который позднее будет назначен по серии. Это дополнительная работа ради перекрытия стадий; в V3 число прочитанных файлов может быть больше числа распознанных. Ошибка предположительно пропускаемого файла не прерывает остальные кадры. Ошибка запрошенного файла записывается в результат. При отсутствии лица сохраняется исходный повторный проход V2.

В отчёте `seconds` — реальное время всей обработки, включая завершение фоновых чтений. `timings.decode` у V3 — ожидание подготовленных кадров и синхронные повторные чтения. `pipeline.decode_work_seconds` и `resize_work_seconds` — суммарное время работы фоновых потоков; оно перекрывается с распознаванием и не складывается с общим временем. `versus_v2_series` содержит прямое сравнение V3 с V2 / серии.

Чтобы проверить весь заказ: `--limit 3000 --mode compare_v3`. Сначала проходит V2, затем V3; файловый кеш и нагрузка компьютера влияют на цифры. V3 добавлена в лабораторию, рабочая сортировка теперь использует V3.

### Замер V3 от 21 сентября 2026

На тех же 1000 JPEG заказа, что и в пользовательском отчёте `02c838b4b59849429c29b92106d73281`, свежий последовательный замер дал: V2 / серии — 97,50 с; V3 — 66,66 с (1,46×, сокращение времени примерно на 32%, около 900 снимков/мин). В обоих результатах 16 персон, 12 назначений по серии и ноль ошибок. Результаты каждого снимка, включая флаги и опорные кадры, полностью совпали. Назначения в рабочей базе до и после замера совпали. Это одна съёмка без ручной проверки точности; независимый результат хранится в `output/sorting-v3-trial-1000.json`.

## V4 и V5 — добавлены без запуска проверок по просьбе пользователя

В лаборатории есть одиночные режимы V4/V5 и сравнение V3 → V4 → V5. «Все версии» теперь включает V1, V2, V2 серии, V3, V4 и V5. Старые режимы сохранены. Автоматического подбора настроек и автоматического старта пробы нет.

**V4** наследует ограниченную параллельную подготовку V3 и шаг серии 2. Детектор работает на стороне 960 или 1120 пикселей; координаты лица и пяти ориентиров переносятся на рабочее изображение до 1600 пикселей для вырезания лица и SFace. Отсутствие единственного лица, сторона лица меньше 40 пикселей или уверенность детектора ниже 0,95 приводят к полному проходу. Неизвестная/неуверенная персона при наличии групп также перепроверяется полным проходом до добавления образца. При отсутствии вектора сохраняется повторное чтение исходного JPEG. Эти условия не гарантируют совпадения с V3: уверенно ошибочное совпадение или пропущенное маленькое второе лицо остаются возможными.

Настройки V4/V5: подготовка 1/2 потока, OpenCV 1/2/4 потока, размер поиска 960/1120. По умолчанию 1 поток подготовки и 2 потока OpenCV; оптимальность не измерялась. Глобальное число потоков OpenCV меняется под общей блокировкой обработчика и восстанавливается в `finally` после каждой версии. В отчёте сохраняются настройки и число полных проходов.

**V5** использует V4 и начинает с шага 2. После двух подряд подтверждённых интервалов шаг увеличивается на 1, до выбранного максимума 3 или 4. Уверенно распознанные крайние кадры должны принадлежать одной персоне; все промежуточные превью должны быть близки к обоим крайним. Сохраняются совпадение префикса, числовые разрывы не больше 3 и близкие пропорции. При любом расхождении все промежуточные кадры распознаются, а шаг сбрасывается на 2. Любое возвращение персоны сопоставляется со всеми группами. Предположения не используются как опорные кадры или образцы лиц.

V5 может пропустить другого человека или групповой кадр между совпадающими опорами. Все такие назначения сохраняют `uncertain=true`, `source=sequence`, ссылки на опорные кадры и размер интервала. Предположения доступны в фильтре проверки. Очередь подготовки ограничена `max_step + 1` изображениями, чтобы сохранить промежуточные кадры до решения о пропуске. Число интервалов каждого шага записывается в отчёт. Прямые сравнения V4 с V3 и V5 с V4 находятся в `relative`.

Скорость и качество V4/V5 ещё не проверены. Эти версии работают только в лаборатории и не применяют результаты к рабочим группам.

## V3 в основной обработке

Новые загрузки и повторная обработка ошибок используют V3: два потока подготовки, окно три изображения, YuNet/SFace на рабочей стороне до 1600, опорные кадры через один и прежние критерии серии. Существующие готовые снимки не пересортировываются. Лаборатория остаётся отдельной: её результаты не применяются к заказам.

Обработчик забирает доступные ожидающие снимки одного заказа, сортирует по числовым именам и сохраняет каждый результат отдельной транзакцией. Новые загрузки попадают в следующий пакет, поэтому границы пакетов и уже существующие группы могут отличать результат от лаборатории с пустыми группами. При маленьких пакетах эффект параллельной подготовки и серий меньше. Перед назначением по серии проверяется актуальный состав заказа: между опорами не должно быть другой уже загруженной фотографии. Полноценного подтверждения конца загрузки здесь нет.

Векторы реально распознанных лиц сопоставляются с актуальными группами в базе, включая ручные переносы. Предположения сохраняются без вектора с флагом проверки. Версия, источник назначения и опоры хранятся отдельно в `photo_analysis`; исходные записи не мигрируют и не перезаписываются. При удалении снимка метаданные удаляются каскадно; перезапуск возвращает незавершённые снимки в очередь.

## Выбор персоны по фотографии и подсказки

В обоих интерфейсах назначение открывает карточки с портретом, именем/номером и количеством фотографий. Выбранные снимки показаны сверху; есть поиск по подписи и создание новой персоны. Ничего не выбрано заранее; назначение требует выбора карточки и нажатия кнопки.

Подсказки вычисляются при открытии окна через `/api/orders/{order_id}/person-suggestions`. Используются сохранённые векторы; модель повторно не запускается. Выбранные снимки и неуверенные образцы исключаются из базы сравнения, чтобы фото не сравнивалось само с собой. Показываются до трёх кандидатов по косинусному сходству и возможная персона по соседям. Это текущие оценки относительно нынешних групп, не сохранённая история первоначального распознавания.

Поддержка соседями требует одного непосредственного предыдущего и одного следующего снимка в числовом порядке, одинакового префикса, положительных разрывов не больше 3, уверенных назначений одной персоне и наличия векторов у обоих. Соседи не могут входить в текущий выбор. Комбинированная подсказка требует, чтобы эта персона была лучшей по лицу со сходством от 0,35 и отрывом от второго кандидата от 0,03. Эти пороги относятся только к подсказкам и не меняют пороги автоматической группировки V3. Подтверждение пользователя обязательно; база от запроса подсказок не меняется.

Сходство не является процентом вероятности. При `no_face`, `multiple_faces`, `small_face` или назначении по серии без вектора оценка лица отсутствует. Совпадающие соседи могут дать только подсказку по порядку, но не доказательство личности. Для нескольких выбранных кадров подсказки могут относиться к разным людям — интерфейс об этом сообщает.

### Уверенное совпадение от 0,93 в основной V3

По запросу пользователя основная обработка принимает лучшую персону при косинусном сходстве с её образцом от 0,93 включительно, не требуя прежнего среднего по группе и отрыва 0,07. При точном равенстве лучших оценок двух персон автоматический выбор не делается. Ниже 0,93 остаются прежние критерии. Лабораторные версии сохраняют исходные правила для сопоставимости замеров. Правило действует при обработке новых/повторно обрабатываемых снимков; уже готовые группы не пересортировываются, кнопка ручного подтверждения по-прежнему подтверждает текущее назначение.
